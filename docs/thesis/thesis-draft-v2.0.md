## РОЗДІЛ 1. АНАЛІЗ ПРЕДМЕТНОЇ ОБЛАСТІ ТА ІСНУЮЧИХ РІШЕНЬ (~18 стор.)

### 1.1. Життєвий цикл ML-моделей та інфраструктурні виклики
- Етапи: підготовка даних → тренування → валідація → розгортання → моніторинг
- Типові проблеми: dependency hell, невідтворюваність, ручне розгортання
- Поняття MLOps та його зв'язок з DevOps

### 1.2. Контейнеризація як підхід до вирішення інфраструктурних проблем
- Принципи контейнеризації, відмінність від віртуалізації
- Docker: архітектура, образи, контейнери, реєстри
- OCI-стандарт та його значення для переносимості

### 1.3. Оркестрація контейнерів
- Kubernetes: архітектура, основні абстракції (Pod, Deployment, Service, Ingress)
- Порівняння: Docker Compose vs Kubernetes vs Nomad
- Helm як пакетний менеджер для Kubernetes
- Легкі дистрибутиви: k3s, Minikube, kind — порівняння для локальної розробки

### 1.4. Аналіз існуючих платформ для ML у контейнерах
- MLflow: трекінг, реєстрація моделей, сервінг
- Kubeflow: повноцінна MLOps-платформа
- Seldon Core, BentoML, KServe — альтернативи для сервінгу
- Порівняльна таблиця рішень за критеріями (складність, масштабованість, зрілість)

### 1.5. Підтримка GPU у контейнерних середовищах
- NVIDIA Container Toolkit та nvidia-device-plugin
- Особливості GPU-інференсу у Kubernetes

### Висновки до розділу 1
- Узагальнення виявлених проблем та вимог до системи
- Визначення напрямків вибору технологічного стеку

## РОЗДІЛ 2. ВИБІР ЗАСОБІВ РЕАЛІЗАЦІЇ (~12 стор.)

### 2.1. Вибір платформи контейнеризації
- Обґрунтування вибору Docker як основного інструменту
- Стратегія multi-stage builds: переваги для ML-образів
- Вибір базових образів (slim vs full) та обґрунтування

### 2.2. Вибір платформи оркестрації
- Обґрунтування вибору Kubernetes
- Порівняння локальних дистрибутивів: k3s vs Minikube vs kind — обґрунтування k3s
- Обґрунтування вибору GKE Autopilot для хмарного середовища
- Helm як інструмент керування розгортанням: обґрунтування вибору

### 2.3. Вибір інструментів ML-компонента
- Обґрунтування вибору PyTorch як ML-фреймворку
- Вибір датасету (CIFAR-10) та архітектури моделі (MobileNetV2 / ResNet-18)
- Обґрунтування вибору MLflow для трекінгу експериментів
- FastAPI як платформа REST API інференсу: обґрунтування

### 2.4. Вибір інструментів CI/CD
- Обґрунтування вибору GitHub Actions
- GitHub Container Registry (ghcr.io) як реєстр образів
- Стратегія версіонування образів

### 2.5. Вибір інструментів моніторингу
- Обґрунтування вибору Prometheus для збору метрик
- Grafana як інструмент візуалізації: обґрунтування
- Визначення ключових метрик системи (latency, throughput, error rate, resource usage)

### 2.6. Вибір підходу до A/B тестування моделей
- Обґрунтування Canary deployment як стратегії
- Альтернативи (blue/green, shadow) та причини вибору canary

### Висновки до розділу 2
- Зведена таблиця обраного технологічного стеку з обґрунтуванням

## РОЗДІЛ 3. ПРОЄКТУВАННЯ КОНТЕЙНЕРНОГО СЕРЕДОВИЩА (~18 стор.)

### 3.1. Вимоги до системи
- Функціональні вимоги (таблиця)
- Нефункціональні вимоги: відтворюваність, портативність, масштабованість, спостережуваність
- Технічні обмеження (апаратні, бюджетні)

### 3.2. Архітектура системи
- Загальна структурна схема (компоненти та їхня взаємодія)
- Діаграма розгортання (UML Deployment Diagram): k3s homelab vs GKE
- Контейнерна архітектура: train image, serve image, monitoring stack
- Мережева взаємодія компонентів у Kubernetes-кластері

### 3.3. Проєктування CI/CD пайплайну
- Схема пайплайну: lint → test → build → push → deploy
- GitHub Actions як платформа автоматизації
- Стратегія тегування образів та версіонування

### 3.4. Проєктування системи моніторингу
- Архітектура: Prometheus → Grafana
- Визначення ключових метрик (latency, throughput, error rate, resource usage)
- Стратегія алертингу

### 3.5. Проєктування механізму A/B тестування моделей
- Canary deployment: архітектура з двома Deployments
- Розподіл трафіку через Service/Ingress
- Критерії порівняння версій моделей

### 3.6. Проєктування Helm-чартів
- Структура чарту: templates, values, helpers
- Параметризація для різних середовищ (dev/prod, CPU/GPU, local/cloud)

## РОЗДІЛ 4. РЕАЛІЗАЦІЯ ТА ЕКСПЕРИМЕНТАЛЬНЕ ДОСЛІДЖЕННЯ (~22 стор.)

### 4.1. Реалізація ML-компонента
- Опис датасету (CIFAR-10) та моделі (MobileNetV2 / ResNet-18)
- Скрипт тренування з інтеграцією MLflow
- REST API інференсу на FastAPI

### 4.2. Розгортання на локальному кластері (k3s)
- Встановлення та конфігурація k3s на Asus homelab

- Налаштування nvidia-device-plugin для GPU-інференсу

### 4.3. Налаштування CI/CD
- Конфігурація GitHub Actions workflow
- Інтеграція з GitHub Container Registry (ghcr.io)
- Демонстрація автоматичного деплою при push у main

### 4.4. Впровадження моніторингу
- Розгортання Prometheus та Grafana у кластері
- Конфігурація дашбордів та алертів

### 4.5. Реалізація Canary Deployment
- Створення двох версій моделі
- Налаштування розподілу трафіку
- Збір та порівняння метрик двох версій

### 4.6. Розгортання на GKE Autopilot
- Конфігурація хмарного кластера
- Деплой тим самим Helm-чартом без змін
- Порівняння з локальним кластером

### 4.7. Експериментальне дослідження
- Бенчмарки: CPU vs GPU інференс (latency, throughput)
- Порівняння: k3s (локально) vs GKE (хмара) — час розгортання, latency, ресурси
- Навантажувальне тестування (wrk / locust)
- Аналіз результатів, таблиці, графіки
